# GRC Risk Register & Control Mapping

A demonstration **Governance, Risk, and Compliance (GRC)** project showing how I build and operate a risk register, map controls across multiple frameworks, and track risks from identification through treatment and review.

> **Note:** This is a portfolio project built on a **fictional company ("Nimbus SaaS Co.")** using **public, standard frameworks**. It contains no real company data, account IDs, or confidential information.

---

## What this project demonstrates

- **Risk identification and scoring** using a 5×5 Likelihood × Impact model
- **Risk treatment** — mitigations, residual risk, and ISSM/management acceptance workflow
- **Control mapping** across **SOC 2**, **ISO/IEC 27001:2022**, and **NIST SP 800-53**
- **Review cadence** tied to risk rating (continuous monitoring)
- Clear, audit-ready documentation an analyst would hand to an auditor or control owner

These are the day-to-day skills of a GRC / IT Risk / Compliance Analyst.

## Scenario

**Nimbus SaaS Co.** is a fictional early-stage SaaS company pursuing **SOC 2 Type II** and preparing for **ISO/IEC 27001** certification. This project documents its information security risk register and the controls that reduce those risks.
